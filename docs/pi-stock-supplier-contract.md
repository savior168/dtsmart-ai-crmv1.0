# PI 变更、回货来源与供应商对账契约（开发中，未发布）

本契约把销售单、仓库实物和财务账款分成三本账。不得通过改写已发生的回货或交货代记录来“同步”PI。

## PI 变更

- 只有实际创建该 PI 的账号可撤回、编辑、提交或发起变更：销售员、主管、跟单员都可按管理员配置的菜单/操作权限参与，但归属销售员不得代改跟单员创建的单，管理员也不得越过创建者范围直接改他人 PI。数据范围由服务端和数据库同时校验，按钮隐藏不算授权控制。
- 仓库尚未开始处理、全部产品仍为 `WAITING` 且回货/理货/交货代数均为零：销售可无限次撤回、修改并重新提交。现有撤回路径继续使用；必须按备货单版本锁检查，避免与仓库开始处理竞争。
- 仓库开始处理后、整单交货代前：最多三次**已生效**的销售变更；被驳回或主动取消的申请不消耗次数。一次申请可包含多行变化，提交时锁定 PI 与备货单，记录基准版本和完整前后快照。申请待决时仓库可继续查看，但涉及的未发货产品行暂停新的采购/回货/理货/交货代；不影响其他行。
- 仓库必须确认每一份仓库开始处理后的变更；“需要实物复核”是更严格的附加条件，不能把无需退货/重新分配误认为无需仓库确认。申请人只能是该 PI 创建人，归属销售员、主管、管理员均不能代其变更。
- 任一产品行 `shipped_quantity > 0`：该行身份、质量、数量、价格均不得变更；新增未发货行可另行申请。整单全部交货代后不能发起变更，退货或补单须走新业务单据。
- 变更类型：新增、取消、数量增减、质量/型号/品牌替换、售价或销售预估成本调整、仓库中文规格/要求调整、交付日期/地址/联系人调整。相同类型/品牌/型号但质量不同也视为替换，不能合并覆盖旧行。
- 任何减少低于已回货/已理货数量、删除已有实物的产品行、或改变其产品身份时，先挂起；仓库确认退回/重新分配的实物去向后，在同一数据库事务内生效。已交货代数量从不回退。
- 生效事务同时更新 PI、报价快照、未交货代的备货行、版本号、逐行差异、审计日志及仓库待办通知。失败全部回滚。仓库列表和详情必须展示版本、确认状态与红删线/绿新增/数量前后值，旧版本仍可追溯。
- PI 详情、备货单详情及备货单预览/打印读取同一版本化变更记录。备货单模板顶部“订单变更说明”由系统自动生成简短摘要（版本、时间、申请/确认人及变更项），下方产品明细逐行标记：新增行标绿、取消行标红且保留旧行删除线、数量显示旧值→新值、质量/型号替换并列展示旧/新。文字标签与数字差异不能只依赖颜色，确保黑白打印可辨；超出摘要栏的差异须续页完整列出，不截断。待仓库确认的申请不得冒充已生效订单内容。打印件须带订单版本与生成时间，避免仓库拿旧纸单执行。
- `PI_CHANGE_REQUESTED` 是仓库高优先级待办：事务内向所有启用仓库员写入通知及订单版本/变更摘要，默认弹窗和语音，弹窗不自动消失；仓库手动查看或稍后处理不等于业务确认。浏览器禁止自动播报时仍须保留可见待办与未读状态。

## 供应商与送货单

- 供应商档案在「采购管理 / 供应商档案」维护。表格中已有的供应商代码（包括现金结）均作为系统代码沿用，并保留为 `legacy_code`；只有新建且确实没有原代码的现金结供应商才生成不可复用的 `CASH-...` 代码。一旦有备货行或送货单关联，系统代码、历史档案代码及结算类型不可改，需停用旧档案后新建；停用是默认删除方式，已有业务关联的供应商不可物理删除。
- 财务角色默认只查供应商和对账并登记付款；管理员如需委托财务维护供应商档案，可单独开启「维护供应商档案」，默认权限不变。
- 仓库每次**增加**某 PI 产品行累计回货数，必须搜索选择或手输精确匹配已启用供应商档案代码，录入该供应商实体送货单号、对应本次回货整数数量及实际采购单价；送货日期必填，备注选填。未知或停用代码不得入账；有维护权限者可在回货弹窗就地新增档案并自动选中，无权限者提示联系管理员。数量/单价/供应商/送货单号在同一事务写入，不允许先增回货数后补来源。
- 默认操作是一项产品登记一笔供应商回货；不同产品可选择不同供应商。仅发生分批或多家补货时重复追加该产品的回货记录，不要求在常规表单预先填写多组供应商。已在同一备货单登记过的纸单可由仓库员主动点选复用供应商/单号/日期，数量和采购价仍须逐笔核对填写；不得暗中沿用上一笔采购价。
- 一张实体送货单可分配到多个 PI 产品行，多个 PI 产品行也可来自多张送货单。按「供应商 + 送货单号」去重成单头，按每次回货分配生成不可静默覆盖的明细事件；每笔分配同时固化回货当时的行号、产品类型、品牌、型号、质量和描述，后续合法订单变更不得改写历史送货事实。无须重复抄录纸单上的全部商品。纸单总金额可选填，若与已分配金额不同，财务显示差额，不伪装已核清。
- 现金结也必须有供应商档案和送货单/收据号；应付金额按回货分配计算。仓库可填“现场实付金额/付款凭证”，但只有财务核准的付款流水冲减应付，不得将现金结自动视为已付款。
- 数量纠错采用有原因、操作者、时间和原事件引用的冲正/补录，不修改或删除历史送货单与回货事件。已交货代的分配不可冲正。

## 成本与对账

- 销售员、主管及跟单员仅可复核**自己创建**的 PI（跟单员代销售创建时归属销售员可查看，但不能代替创建者改），且须由管理员授予独立的 `orders.cost_review` 权限。整单全部交货代后，可在独立“销售成本复核”入口更正销售口径成本，历史前后值与原因留痕，不修改已交货代产品、报价快照、送货单或实际采购价，也不消耗三次 PI 订单变更次数。未复核时沿用最初 PI 成本。整单交货代通知创建者复核，但不包含采购价。
- 主管、管理员可并列查看上述销售口径毛利与按供应商实际回货采购金额、仓库三项费用计算的**实际纯利/纯利润率**，两种口径明确命名，不混作同一指标。实际采购单价和可反推单价的逐行实际毛利不得发给普通销售员；其复核后的估计成本也不得覆盖实际采购账本。
- 包装费在打包/理货时可先登记，出货费在货代交接时登记，其他实际费用发生时登记。未交货代前为可核对的费用草稿，须记用途、凭证和操作人；每次部分交货代时，只将该次确认的费用原子写入该次交接流水并计入整单累计，不能把草稿与交接流水重复相加。交货代后的补录或纠错使用有原因的调整流水，不能覆盖原费用记录。零费用需明确填 0，而非留空。
- 预计或实际纯利 = 产品销售额 − 对应成本 − 仓库记录的包装费 − 出货费 − 其他费用。各费用只扣一次；在整单未交货代前，仅展示已完成交接的阶段费用，不将阶段费用误称整单最终实际纯利。整单完成后，实际纯利润率 = 已核实实际纯利 ÷ 同一批订单的产品销售额；费用未齐或销售额为零不输出误导性百分比。
- 供应商对账按**送货日期**筛选任意起止日期，并提供周、月、季度、年快捷范围；汇总供应商、送货单、PI、产品、数量、应付、经财务确认的已付和未付。可以从供应商→送货单→各 PI 回货分配双向下钻。CSV 导出与页面使用同一过滤条件和同一计算来源；一张送货单拆到多行 PI 时，整张纸单金额、应付、已付、未付和付款凭证仅在首行输出，避免 Excel 按列求和重复计算；匹配送货单超过 5000 张时明确要求缩小筛选范围，绝不静默截断。
- 一笔银行或现金付款可按同一凭证号分配到**同一供应商的多张送货单**；同一送货单不能重复登记同一付款方式和凭证号，也不能把同一凭证跨供应商复用。每张送货单的已付金额不得超过其净分配应付金额；原始付款流水只追加不覆盖。
- 历史没有逐笔送货单的备货记录必须明确标识“待补来源”，不得虚构供应商账款或与新记录混算成已核实金额。

## 验收门槛

先在本机隔离 PostgreSQL 验证并发版本冲突、三次限额、部分/全部交货代锁、实物挂起确认、回货来源必填与多对多分配、冲正、现金结和账期对账、角色数据隔离。正式库测试必须使用可追踪测试记录，结束后逐项核对清理，不得改写已有业务记录；不得为测试新建收费数据库。

供应商迁移分两段发布：`20261102060000` 仅建台账、捕获历史回货基线，不启用强制拦截，确保旧仓库页面在预览验收期间仍能回货；新页面与业务接口验证通过后，再执行 `20261104000000`，在同一事务内锁定备货行、补齐过渡期基线并启用送货单强制校验。若发现台账净回货数大于实物数，第二段迁移整体回滚，不能强行切换。切换后须确认旧回货接口不能绕过送货单、新入口仍能正常登记并反向对账，然后再完成正式发布。正式库迁移历史与本地文件不一致时，不能直接重放整条迁移链或猜测性修复历史记录；必须先核验待应用迁移的真实数据库前置条件和发布顺序。
