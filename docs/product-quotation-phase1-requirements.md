# 商品与报价闭环第一阶段需求基线

## 1. 范围与约束

- 面向 10 人以内外贸团队；无库存数量管理。
- 采购成本以人民币维护，客户报价默认美元。
- 客户付全款并确认后，销售订单进入采购/备货流程。
- 复用现有页面布局、筛选栏、列表、分页、弹框、状态徽标、权限和审计组件。
- 不删除、不改名、不弱化任何现有模块或权限。

## 4. 商品主档

- 系统 SKU 由数据库生成：`ZK-YYMM-000001`，全局唯一、并发安全、创建后不可修改。
- 报价表顶部的“代码”是供应商身份编号，同一供应商的多个商品可共用；它不是商品货号，更不是系统 SKU。逐行供应商货号仅在来源明确提供时保存。
- 必填：商品分类、中文名称；选填：英文名称、适用设备品牌/型号、类型、品质、颜色、包装、单位、MOQ、别名、图片和中英文描述。商品分类明确屏幕、电池、后盖/中框、小配件或其他规格类型，已有关联商品的分类不得直接切换规格类型。
- 新增、编辑、启停均记录审计；停用不删除历史报价引用。
- 重复导入仅能在“供应商身份编号 + 经确认的逐行商品货号”唯一时自动匹配；无单品货号时需要已确认的系统 SKU 或完整可交付规格匹配，遇到歧义不得自动合并、改主档或覆盖价格。

### 多维规格核对

- 商品大类至少覆盖屏幕、电池和小配件；实际分类以完整原始报价表核对结果为准。
- 屏幕须分别识别适用设备品牌/型号、原装或国产等来源、DD/JK 等厂商、Incell/OLED 等显示技术，以及原表明确列出的更细版本、品质、颜色和包装。不同维度不能合并进一个含糊的“品质”值。
- 产品分类与适用设备品牌/系列/型号正交：iPhone、Samsung、MacBook 不是屏幕/电池/后盖的互斥上层分类。同一类商品可适配多个型号，但不同可交付规格和价格须有独立商品变体。
- 通用维度：适用设备、配件类型、原产/来源、生产厂牌、供应商、采购单位、起订量、价格及来源。屏幕另有单片/带框、显示技术及细分技术、尺寸规格、品质/成色；电池另有容量、是否带排线/工具及认证（仅来源明确时）；后盖/中框另有玻璃/后盖总成/中框等装配范围、随附小配件、机型和颜色；充电尾插、排线、摄像头等小配件另有位置、接口/版本和兼容型号。并非每种商品都要求所有维度，字段由配件类型决定。
- `ORG` 表示原装品质；`全新` 在本业务源表中指国产第三方新配件；`拆机` 是旧设备拆出的二手原装件；`原尺寸/大/中/小尺寸` 为尺寸维度；`TFT` 保留原文，未确认具体屏幕技术与品质前不得归为原装或 OLED。单片屏与带框屏分别定价、分别生成 SKU。`LOGO` 为采购/货代物流信息，不因有无 LOGO 单独生成 SKU；空白是未知而不是 NO。
- 机型官方颜色是可核对的参考词表，不等于供应商已提供该颜色的具体配件。后盖总成只有在供应商报价/目录/人工确认明确到“机型 + 装配范围 + 颜色”时，才能创建对应可报价变体并关联价格；没有颜色的源行标记待核对，不得自动复制报价到所有官方颜色。iPhone 17 官方机身颜色为 Black、White、Mist Blue、Sage、Lavender，来源见 Apple iPhone 17 技术规格：https://www.apple.com/iphone-17/specs/；当前提供的《稻田产品价格表》“国产后盖”页有 `17(中框+后盖)` 报价行，却未列出该行实际供货颜色，所以不能由此生成五条已定价 SKU。
- 原表未说明的规格不得从工作表名或价格高低猜测。无法确认的维度保留原文、工作表与单元格，进入人工核对，不能自动发布。
- 同一商品的不同供应商报价与附加包装费用须保留来源和生效版本；是否构成不同销售 SKU 应按实际可交付规格判断，不能仅由供应商编号决定。

## 5. 价格与建议售价

- 成本组成：采购成本 + 包装费 + 其他成本。
- 每类价格可按 MOQ 保存多个档位；指定数量只取不大于该数量的最高档位，不能把多个档位相加。
- 同商品、价格类型、币种和 MOQ 同时只能存在一个当前有效版本；历史版本永久保留。
- 固定报价汇率由管理员维护并记录来源与更新时间；报价保存汇率快照，历史报价不随新汇率变化。
- 建议美元售价取以下较高值，并按设定步长向上取整：
  - 美元成本 × (1 + 加价率)
  - 美元成本 ÷ (1 - 最低毛利率)
- 规则优先级：商品规则 > 分类规则 > 全局规则。
- 已维护的美元销售参考价可作为建议价来源，但必须展示来源；销售可改实际售价。

## 6. 报价闭环

- 销售可按名称、系统 SKU、供应商货号、品牌、型号和别名搜索商品。
- 选择商品后自动带入客户可见名称、品牌、型号、品质、英文描述、MOQ、完整成本、建议售价。
- 销售调整数量后，系统按数量重新匹配价格档位并重新给出建议售价。
- 实际售价可修改；保存时记录商品 ID、SKU、供应商货号、完整成本、建议售价、实际售价、汇率和规则快照。
- 历史报价展示保存时快照，不读取后续变更后的商品价格。
- 客户确认后创建销售订单和备货单，保留商品追溯信息；采购/仓库看不到客户实际售价。
- 报价中的完整成本（采购价＋包装费＋其他费用）不是备货单实际采购单价。销售员只填中文描述和理货要求；采购/仓库人员依据实际采购确认人民币单价，未确认与明确 0 元必须区分。历史备货金额默认未核实，详情及导出不得将其显示为已确认成本。备货单总采购金额仅在所有明细均确认后显示。

## 7. 产品报价表导入

- 支持 xlsx/xls，多工作表逐表解析；保留文件哈希、工作表、原始行、原始单元格和原值。
- 标准明细按明确列头映射；矩阵表只在型号、品质、装配方式与价格有可核对的一一对应关系时预填，复合单元格保留原文待核对，不凭邻近数字猜测。
- 必须用完整原始工作簿逐表对账：来源非空行、识别候选、核对/跳过项与发布项都要可追溯；未取得原始工作簿时不能宣称导入覆盖率或准确率已验收。
- SKU 缺失不是复核原因，发布时自动生成系统 SKU。
- 支持按状态/工作表搜索、批量确认和批量跳过。指定采购人员可将同一来源单元格的多个商品逐项拆分，拆分记录保留真实单元格地址、子序号和互不重叠的原文片段；原整格保留待核对直到操作人明确确认拆分完成，且不得与拆分子项重复发布。子项默认为待核对。
- 经授权人员可勾选已核准记录分批发布；待核对、错误及尚未解析内容继续隔离，不能借部分发布变为正式商品。整批发布仍须先清空错误和待核对，并解决未覆盖工作表。
- 同一文件重复上传返回原批次；重复发布幂等；同商品不得重复创建。
- 每次所选发布操作必须原子执行；任一行失败则本次所选全部回滚，已发布的既有批次记录不被回滚或覆盖。

## 8. 验收标准

- 数据库迁移可重复执行，不破坏现有数据。
- SKU 并发生成无重复；现有 SKU 不变。
- 多 MOQ 示例验证成本只取正确档位。
- 定价公式、最低毛利和取整分别有边界测试。
- 报价选品、保存、重开、修改、确认和下游单据均保留快照。
- 报价和备货要保留保存时的品类专有规格与颜色快照；PI 导出、打印页及备货详情和模板展示对应保存时的颜色，不因商品主档后续编辑而变化。
- 销售、采购/仓库、主管、管理员权限分别通过 API 与页面验证。
- 导入覆盖标准表、矩阵表、重复文件、重复发布、错误行和批量复核。
- 全量测试、构建和生产部署成功后，再进行生产页面/API/日志验证。

- 旧版导入批次可能记录了偏移的来源坐标，或将邻近数字/合计误拼入商品名称、品质及采购价；非 `A1-V12` 解析批次不可编辑或发布。同一原始文件可按新版重新解析另建批次，保留旧批次供审计，不覆盖人工核对记录。
- “iPhone拆机后盖”与“三星拆机后盖”同一单元格含多个机型、颜色、区域版和价格，不能安全自动拆成 SKU；可由采购人员逐格拆分并核准后单独发布，未核准内容仍阻断整批发布，不能随意选一个价格。
- “国产后盖”同时含多个装配范围、供应商编号和一体/分体版本；通用矩阵识别仅用于定位核对项，不能把同页首个供应商编号套用于全部列，也不能从 `17(中框+后盖)` 衍生未列出的颜色。
- 其余矩阵页的数字只作为定位线索，不预填采购价、商品名、型号或整表供应商编号（同页可能有多个供应商报价区）；这些页一律记为未完整覆盖，前端和数据库函数均阻断整批发布。候选数量不是商品准确率或导入覆盖率。允许已核准单品分批发布，但完成全部来源对账前不得宣称整份报价表已导入完成。
